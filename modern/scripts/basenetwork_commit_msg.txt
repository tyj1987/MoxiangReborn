Phase 7.1: legacy [Lib]BaseNetwork migration (.vcproj -> CMakeLists.txt)

- Convert [Lib]BaseNetwork/BaseNetwork.vcproj (VS 7.10 / 2003 DLL
  format) into a CMakeLists.txt. Uses Visual Studio 17 2022 generator
  with -A Win32 (legacy source uses __declspec(naked) + __asm which
  x64 MSVC does not support; tracked in docs/KNOWN_BUGS.md Bug C-10).
- Replace <afx.h> + <ole2.h> with <objbase.h> (modern COM).
- Force WinSock 2.0 mode via #define _WINSOCKAPI_ before <windows.h>
  so WinSock 1.1 is suppressed.
- Add /Zc:strictStrings- so legacy TCHAR-style calls with string
  literals still compile (matches legacy vcproj behavior).
- Add NDEBUG fallback for _CrtCheckMemory() — legacy network.cpp
  used it unconditionally but it only exists in _DEBUG; without the
  fallback Release builds would fail to link.
- network.cpp now #include "stdafx.h" first so winsock2.h is in
  scope before <mstcpip.h> pulls it.
- BaseNetworkDll.cpp kept its leading '#define UNICODE' (the COM
  registration code needs wide TCHARs); CMakeLists backs it up with
  /Zc:strictStrings-.

Build artifact: BaseNetwork.dll (99840 bytes), BaseNetwork.lib
(1572 bytes), BaseNetwork.exp (1554 bytes). Exports match the
.def file: DllCanUnloadNow, DllGetClassObject, DllRegisterServer,
DllUnregisterServer.
